# AI 활용 과정 · 본인 역할 · 검증 범위

이 문서는 넷마블네오 AI Game Maker 지원을 위해 프로젝트별 AI 사용을 구분한 설명 자료입니다. 코드의 AI 생성 비율이나 생산성 향상 수치를 사후에 추정해 기재하지 않습니다.

## 1. Unity Skill Logic Prototype (2026.07)

**형태:** 개인 기술 학습·프로토타입 / Unity C# / 강의 참고 + AI 에이전트 보조 구현

| 단계 | 실제 작업 | 본인 수행 범위 |
| --- | --- | --- |
| 개념 학습 | 인터넷 강의로 Unity 전투 스킬 개념 학습 | 학습·프로토타입 목표 설정 |
| 구현 | 구현·오류 발생 시 AI 에이전트에게 코드 생성 및 수정 요청 | 오류 상황과 목표 동작을 설명하고 코드를 프로젝트에 적용 |
| QA 시나리오 | AI 에이전트로 QA 목록 초안 생성 | 테스트 대상을 선택·정리 |
| 오류 검증 | Unity에서 실제 실행 | 정상·실패·경계 조건과 오류 직접 확인 |
| 수정 반복 | 의도와 다른 동작의 수정안을 AI에 재요청 | 결과 재실행 및 검증 |
| 문서화 | AI 에이전트의 기술 설명·문서 정리 도움 | 실제 구현·검증 내용을 토대로 확인 |

**검증 사례:** 대상 없음 / 사거리 초과 / 쿨타임 중 재사용 / 사망 대상 / Normal·DoT·Area / 다중 Collider 중복 피해 / UI 상태. 검증 문서의 일부 예상 결과는 AI의 QA 초안에서 출발했으므로 '전 항목을 독자적으로 설계'했다고 표현하지 않습니다.

**표기 원칙:** `1인 프로젝트`와 `전체 C# 코드 100% 직접 작성`은 다릅니다. AI 생성·수정 코드를 포함하며 직접 작성 비율은 미산정입니다. 단독 책임을 가졌다는 사실과 코드 저작 비율을 동일시하지 않습니다.

**면접에 대비해 확보할 실제 사례:** AI 제안이 최초 기대와 달랐던 오류 1건의 증거(프롬프트/문제 상황, 변경 전후 코드, Unity 재현 조건, 확인 결과). 현재 대화에서 정확한 최초 프롬프트·발생 시각·수정 횟수는 확인되지 않았으므로 작성하지 않습니다.

## 2. Unity QA Companion (2026)

**형태:** AI 코딩 도구로 구현을 보조받은 웹 기반 QA 워크플로 도구.

| 단계 | 역할 |
| --- | --- |
| 업무 설계 | `Issues.md` → 테스트 케이스 생성용 프롬프트 → JSON 응답 검증 → 수동 테스트 → 버그 리포트 관계 정의 |
| 직접 기준 설정 | 이슈·케이스·실행 이력·버그 리포트 데이터 관계, 필수 필드, 참조 관계, 예외 처리 기준 |
| AI 개발 도구 | HTML/CSS/JavaScript UI와 코드 생성·수정 지원 |
| 최종 검증 | AI가 생성한 테스트 케이스는 곧바로 확정되지 않으며, 데이터 구조를 검증하고 실제 빌드의 PASS/FAIL/BLOCKED 판정은 사람이 기록 |

기술 문서: [Unity QA Companion workflow](../03_Technical_Notes/06_UnityQACompanion_AI_Workflow.md)  
데모: https://unity-qa-companion.vercel.app/

## 3. 팀 프로젝트의 AI 사용 범위

`필연과 우연`, `네 발자국`, `Hey Cheese!`의 **게임 개발 성과를 일괄적으로 AI가 수행한 성과로 표시하지 않습니다.** 개인 구현 범위와 팀 공동 성과는 [기여 문서](../01_Project_Contribution.md)를 기준으로 구분합니다. 팀 개발 당시 구체적으로 어떤 AI 모델이 어떤 파일을 생성했는지는 현재 근거가 없으므로 기재하지 않았습니다.
